# AUTOSERVICE

Рабочее пространство автосервиса для приёма заявок, подбора запчастей и закупок. FastAPI обслуживает веб-интерфейс и API, SQLite хранит заявки, выбор, лоты и историю. По умолчанию новый интерфейс работает с четырьмя явно обозначенными демо-источниками.

## Запуск на отдельной демобазе

Требуется Python 3.11 или новее. Выполняйте команды из папки проекта, где находятся `requirements.txt` и `app/main.py`.

### Windows PowerShell

В примере проект находится в `C:\Agent 1`. При запуске из другой папки подставьте её путь.

```powershell
Set-Location -LiteralPath 'C:\Agent 1'
if (-not (Test-Path '.\.venv\Scripts\python.exe')) {
    python -m venv .venv
}
.\.venv\Scripts\python.exe -m pip install -r .\requirements.txt
$env:AUTOSERVICE_DATA_DIR = Join-Path (Get-Location).Path 'data-demo'
.\.venv\Scripts\python.exe -B -m uvicorn app.main:app --host 127.0.0.1 --port 8080
```

Команды вызывают Python из виртуального окружения напрямую, поэтому активация не требуется. Путь `.venv/bin/activate` и запись переменной перед командой относятся к Bash. Чтобы убедиться, что в папке находится новое рабочее пространство, выполните `Test-Path .\app\workspace.py` в PowerShell. Ожидаемый результат — `True`.

### Linux и macOS

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
AUTOSERVICE_DATA_DIR="$PWD/data-demo" python -B -m uvicorn app.main:app --host 127.0.0.1 --port 8080
```

Откройте `http://127.0.0.1:8080` в браузере. В пустой базе нажмите **Создать учебный пример**, чтобы открыть заявку с двумя деталями и сравнить предложения. Можно начать с пустой заявки и добавить автомобиль через **Гараж**. Демо-каталог подтверждает применимость для учебной конфигурации Mitsubishi Pajero Sport. Для других автомобилей известный артикул требует ручной проверки с основанием.

`run.bat` и `run_browser.bat` запускают приложение на Windows. Задайте `AUTOSERVICE_DATA_DIR` перед запуском или в локальном `.env`, чтобы работать с демобазой либо проверенной копией. Сервер продолжает работать после закрытия браузера для выполнения расписания. Если путь к данным не задан, используется существующий каталог `data`. Перед первым таким запуском сделайте резервную копию.

Прежние голосовые заявки, комплекты и обучение доступны локально через `/classic`, а их архив — через `/archive`. Браузерная диктовка зависит от поддержки и разрешения микрофона. Микрофон и запуск Windows проверяются на целевой машине. Для прежней загрузки аудио нужен опциональный `faster-whisper`, который загружает модель при первом использовании. Настройки старого разбора через LLM описаны в [памятке](ПАМЯТКА-LLM.md). Новый предпросмотр разбирает текст локально.

## Как оформляется закупка

- Сотрудник сохраняет черновик, выбирает автомобиль и сравнивает предложения. Выбор и количество сохраняются в SQLite. Цены предложений хранятся в минимальных единицах валюты. Суммы разных валют выводятся отдельно.
- Обычные позиции сохраняются в выбранный лот. Открытый лот закрывается для добавления в 16:00 по Екатеринбургу по умолчанию. Демо-календарь учитывает понедельник–пятницу. После закрытия сотрудник подтверждает группу с одинаковым сроком. Внутри группы создаётся один заказ на поставщика. Для переноса сервер требует явно выбранную следующую рабочую дату.
- Срочную позицию можно подтвердить отдельно в любое время. Перед подтверждённой отправкой сервер сравнивает свежие условия с показанным обзором. При изменении показывает «Было / Стало» и требует новый обзор. При неизвестной доставке требуется явное согласие с предварительной суммой.
- Подтверждение резервирует позиции и записывает постоянный ID операции в одной транзакции. Повтор того же подтверждения возвращает тот же заказ. Для неизвестного исхода есть сверка, а повтор блокируется. Известный учебный отказ можно повторно обработать с тем же ID, если сверка и условия позволяют. Переход в учебный кабинет оставляет заказ ожидающим до записи номера с префиксом `DEMO-`.
- В **Подключениях** доступны учебные сценарии отказа, отсутствия товара, недостаточного остатка, изменения цены или срока, неизвестной доставки, потери ответа и оформления вручную. Диагностика проверяет только чтение.

## Хранение, резервирование и восстановление

Новые таблицы и колонки добавляются при запуске. Старые записи гаража, лотов, заявок, комплектов и истории остаются в существующей схеме. Старые номера и цены отображаются в классическом архиве. Новый журнал заказов строится из новых подтверждений, для которых приложению известны согласованные условия и фактический статус.

Сделайте согласованную копию SQLite через backup API, который учитывает WAL. Целевой файл должен быть новым.

```sh
python -B scripts/sqlite_backup.py data/agent.db /path/to/backups/autoservice-before-workspace.db
python -B scripts/sqlite_backup.py /path/to/backups/autoservice-before-workspace.db /path/to/restore/agent.db
AUTOSERVICE_DATA_DIR=/path/to/restore python -B -m uvicorn app.main:app --host 127.0.0.1 --port 8080
```

Команда проверяет целостность и внешние ключи. Проверьте копию в отдельном каталоге и сохраните исходный файл. Загруженные аудиофайлы и другая локальная информация вне SQLite резервируются отдельно. Резервную копию храните с ограниченным доступом.

Миграция и восстановление проверены на резервной копии базы из репозитория. Сверены 3 автомобиля, 37 заявок, 73 позиции, 5 классических лотов, 103 события, каталог, обученные записи и настройки. Все исходные значения сохранились. Рабочая копия `data/` в процессе разработки не использовалась для записи.

## Общий доступ

Локальный режим разрешает работу с loopback-адреса браузера. Для общего доступа нужны HTTPS и переменные окружения `AUTOSERVICE_USERS` и `AUTOSERVICE_SESSION_KEY`. Первая содержит JSON-словарь пользователей с полями `password` и `role`. Вторая содержит случайный секрет подписи длиной от 32 байт. Передавайте значения через защищённую конфигурацию развёртывания. Формат справочного файла приведён в `.env.example`.

Роли в одном общем рабочем пространстве:

- `employee` — гараж, черновики, поиск, просмотр и личные настройки.
- `buyer` — те же действия, подтверждение закупок, ручная регистрация и сверка.
- `admin` — все действия и управление общими настройками и демо-источниками.

Сессия подписана, cookie устанавливается с `Secure`, `HttpOnly` и `SameSite=Strict`. При проксировании передавайте схему HTTPS и исходный Host через доверенный прокси. В общем режиме классический интерфейс и его API отключены. Права не разделяют данные на отделы или организации.

## Тесты

```sh
python -B -m unittest discover -s tests -v
node --check web/workspace.js
python -m pip check
```

Для браузерной проверки запустите сервер с **пустым** отдельным каталогом данных. Нужен системный Chromium или установленный Playwright Chromium (`python -m playwright install chromium`).

```sh
python -B tests/browser_workspace.py --url http://127.0.0.1:8080 --shots /tmp/autoservice-shots
```

Пройдены 12 серверных тестов, включая конкурентное подтверждение, обновление условий, частичные результаты, ручную регистрацию, восстановление прерванной операции и проверку прав. Браузерный сценарий проверяет прямые ссылки и перезагрузку семи разделов, макет на 1920×1080, 1600×900, 1366×768 и 1024×768, разбор заявки, выбор, сохранение в лот и срочное оформление до истории. Рисунок машины заменён нейтральной иконкой. В сравнительную таблицу добавлен полный итог, а цены и адреса учебные.

## Рабочие интеграции

Реальные заказы в текущей версии заблокированы. Существующие адаптеры и их сценарии чтения сохранены для отдельной проверки. Номера черновиков прежней браузерной автоматизации не считаются подтверждением заказа.

| Источник | Что есть в прежнем коде | Что нужно подтвердить до рабочего запуска |
| --- | --- | --- |
| Росско | Поиск SOAP по артикулу, ссылки на VIN-каталог и личный кабинет | Официальный HTTPS-адрес, тестовые ключи, регион и пункт выдачи, поля цены и остатка, отправка и сверка |
| ПартКом | B2B-поиск `/search/parts`, ссылки на кабинет | Тестовый B2B-доступ, лимиты, регион, доставка, контракт оформления |
| Emex | SOAP-поиск по артикулу, ссылка на кабинет | Тестовые учётные данные, доступ с IP, подтверждённый HTTPS-адрес, формат остатков и сроков |
| Exist | Поисковые ссылки и заготовка перехода в личный кабинет | Предоставленный канал цен и наличия или согласованный ручной сценарий, регион и номер заказа |

Для рабочего запуска нужны подтверждённый каталог применимости либо проверяемая OEM-привязка, согласованный регион и календарь, правила доставки и минимум два проверенных канала цен и остатков. Фактические внешние условия и оформление не проверялись. Демо-сверка работает с локальной учебной квитанцией. Перевод старого архива в новую схему заказов потребует сопоставления данных о поставщиках и статусах, которых не было в прежних записях.
